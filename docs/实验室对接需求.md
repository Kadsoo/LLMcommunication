# Step9 实验室通信系统对接需求

目标：把本项目的 `Transport` 从 TCP 换成实验室提供的通信接口，实现软硬件联通。
代码侧只需实现 `transport/adapter.py` 中的 `LabTransport`（现为抛错的空类），上层 Agent 代码无需改动。

## 向实验室确认的问题清单

1. **接口形态**：提供什么？（Socket 协议文档 / 中间件 SDK / 硬件串口+驱动 / 网口 MQTT 等）
2. **传输原语**：是否支持"发一块字节 + 收一块字节"的同步调用（对应 `send/recv`）？还是异步/事件驱动？
3. **帧格式**：长度前缀？分隔符？最大包长？（我们现在是 4 字节长度前缀 + JSON，包最大约 50MB）
4. **地址与端口**：固定 IP/端口，还是需要注册/发现机制？
5. **带宽与延迟预算**：实验室系统支持多大吞吐？KV 传输需要 ~50MB/题（0.6B）~ 数百 MB/题（4B）
6. **鉴权/安全**：是否需要握手、加密、认证？
7. **资源限制**：连接数、并发、保活机制、断线重连策略

## 我方接口契约（供实验室对齐）

```python
class Transport:
    def send(self, msg: dict) -> None       # msg={"type": "TOKEN"|"KV", "data_b64": ..., "meta": {...}}
    def recv(self, timeout: float | None) -> dict
    def close(self) -> None
```

- 两端必须保持相同传输语义：`send` 同步发送完成返回，`recv` 阻塞直到收到一帧
- 负载编码：`data_b64` = base64(序列化字节)；TOKEN 为文本 UTF-8，KV 为 torch 序列化张量

## 建议排期

- 软硬件联调 → 0.5 天（先传 TOKEN 文本验证通路，再传 KV）

## 风险

- KV 包大（4B 模型全量 KV 数百 MB）：实验室链路吞吐不足时，方案一是先上 Step10 的 Delta KV（压缩 3-50x），方案二是分片传输
- transformers 版本差异导致 KV 结构不兼容：两端锁同版本
